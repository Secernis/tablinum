# Tablinum — Style Reference

> A tool that reads Git histories and builds analyses from them. The interface
> should show the data, not itself.

**Origin:** structure, component catalogue and layout rules come from the
TailGrids v3 reference. **Everything that carries the brand** — colours, type,
usage rules — comes from `design/tokens/brand.lock.json` and replaces the
TailGrids defaults.

**This file makes no decisions.** The token block below is generated; to change
a value, change `brand.lock.json` and run `python design/build-all.py`. Every
other line here is prose about applying those values.

## Where Tablinum differs from TailGrids — and why

| TailGrids v3 | Tablinum | Reason |
|---|---|---|
| DM Sans as the only typeface | **Lora** (wordmark, headline) + **Familjen Grotesk** (UI) | The wordmark needs a voice with character, the interface does not. Sticking to one family is a TailGrids house rule, not a law. |
| Primary `#3758F9` (indigo) | **`#9a5b2c`** (Tabula) | Own palette, tuned to WCAG AA in light and dark. The deciding factor was the domain: green and red are taken by diff semantics in Git interfaces, so the brand has to stay clear of them. |
| DM Sans via Google Fonts import | local `@font-face` from `public/fonts/` | A desktop app should not borrow its own typeface from a third party: the import costs a round trip at startup, flashes the fallback face on a poor connection, and sends the user's IP to Google. Tablinum may otherwise use the network — it works with Git remotes. |
| Extended accents (indigo/purple/pink/teal) | **not used yet** | Meant for data visualisation. Once Tablinum shows charts this becomes a real question — and the answer has to stay clear of the diff colours. |
| JetBrains Mono as `--font-mono` | **adopted** | Matches our own choice. Latin subset, 18 KB, digits measured monospaced. |

## The colours of the domain

In Tablinum, green and red belong to **the diff, not the brand**: added,
removed, check passed, check failed. They are therefore not part of the brand
ramp and are not derived from it. Before introducing a new signal colour, check
that it reads apart from those two — a user must never have to guess whether a
surface means "brand" or "good/bad".

## Typography

Four roles, each with a purpose:

| Role | Typeface | Used for |
|---|---|---|
| **Wordmark** | Lora, 600 | The logo only. Outlined during the build — no font dependency downstream. |
| **Headline** | Lora, 600 | Page titles, section headings. |
| **Body / UI** | Familjen Grotesk | Everything operable: labels, buttons, lists, help text. |
| **Numbers & mono** | JetBrains Mono | Statistics, timestamps, durations, hashes, technical markers. |

**Numbers never belong in the display face.** Lora does carry `tnum`, but its
digits are proportional — without the feature enabled, columns wander. JetBrains
Mono is measured monospaced and needs no feature at all
(`design/logo/fonts/audit.json`). Its zero is dotted by default, which keeps 0
and O apart in hashes and values.

TailGrids' size and line-height scale applies unchanged (12/13/14/16/18/20/24/30/36 px,
line heights 1.20–1.75). Negative tracking (`-0.02em`) is reserved for large
headlines, never body text.

## The mark in the interface

| Rule | Value | Enforced in |
|---|---|---|
| Clear space all round | 0.5 × mark height | `src/lib/brand/Logo.tsx` (padding + warning) |
| Minimum size, mark | 20 px (hard floor 16 px) | `build-platform.mjs` aborts below it |
| Minimum size, lockup with tagline | 200 px wide | same |
| Below 100 px | flat variant instead of the gradient | `build-platform.mjs` |
| Below 40 px | simplified version of the mark | `small-icons.mjs` |

These values are **measured, not estimated**. Rendering the mark from 12 to
48 px and counting along scan lines: the three nodes of the commit chain stay
apart from 12 px in the simplified version and from 16 px in the full one. The
20 px minimum adds one step of margin.

A side finding from the same measurement: the two open nodes only show their
holes from 48 px. Below that they are filled dots — which is exactly why the
simplified version exists.

**The one documented exception:** `favicon-16.png`. 16 px is dictated by the
operating system; the arch silhouette survives, the joints do not. Recorded as a
justified exception in `brand.lock.json`.

## Spacing and shape

Unchanged from TailGrids: 4 px base (Tailwind scale), 8 px border radius as the
default (4/8/12/16/24/full), 24 px card padding (16 px compact), 8–12 px between
elements.

## Material

The surfaces are glass — translucent, with their own light. Defined once in
`src/material.css` as `.glass`, `.glass-bar` and `.elev-1/2/3`, on top of the
tokens, for both themes through `light-dark()`.

Four ingredients, and the last two are the ones usually forgotten:

1. A translucent fill — a gradient, never a flat colour.
2. `backdrop-filter`: blur plus saturate.
3. A **lighter edge at the top than at the bottom**. That is what makes an
   edge read as a lit rim instead of an outline.
4. A light source **inside** the surface (`.glass::before`), so every card
   looks the same wherever it sits. The alternative — colour fields behind the
   app — makes a card's look depend on its position, and two identical rows
   render differently. The ground therefore stays quiet: a flat brightening,
   a vignette, grain.

Elevation is a system of three steps, each **layered and tinted** with the
brand's ink rather than one step of black: `elev-1` for tiles, `elev-2` for
cards, lists and tables, `elev-3` for dialogs. A single-step `#000` shadow is
the surest sign of a shadow nobody thought about.

**Nothing opaque on glass.** Hover, dividers, chips, outline buttons, inputs
and skeletons use a mix of the text colour (`bg-ink/6`, `divide-ink/8`),
which brightens on the dark theme and darkens on the light one. An opaque
`bg-raised` on a glass card reads as a patch; an opaque `border-line` reads as
a foreign edge. `src/theme-bridge.css` binds the TailGrids component tokens
the same way.

Kept deliberately minimal: blur 20 px, fills between 3 and 9 percent, no
strong colour fields. It is meant to be felt on the surfaces, not noticed as
an effect. The sibling project this was learned in is Skjol; its
`docs/CHECKLISTE-DESIGN.md` holds the longer reasoning.

## Components

The TailGrids v3 catalogue applies — buttons, cards, inputs, select, checkbox,
radio, toggle, badge, alert, tooltip, avatar, breadcrumb, pagination, table,
tabs, dropdown, modal, progress, skeleton. Look up geometry and behaviour there;
**colours always come through token names**, never as hex in the markup.

Components are added through the CLI and land in `src/components/tailgrids/`:

```bash
npx @tailgrids/cli@latest add table
```

They are left unchanged; adjustment happens through `className`. `twMerge` in
`@/utils/cn` makes sure token utilities override the built-in classes instead of
stacking with them.

## Do

- Use token names (`bg-surface`, `text-muted`), never hex values in markup.
- Exactly **one** filled primary button per view; everything else is secondary
  or ghost.
- Set number columns in JetBrains Mono so they line up.
- Layer surfaces as the ground (`canvas`) and glass cards on it; on glass,
  states are `ink/N` mixes, never an opaque surface token.
- Colour data by entity, never by rank: the language hues live in
  `src/ui/shared/language-colors.ts`, validated for colour vision on both
  surfaces, with green and red left to the diff.
- Use semantic colours (success/warning/danger/info) for their meaning only,
  never decoratively.
- Embed the mark through the Logo component — it brings clear space and the
  minimum-size warning with it.
- Run `python design/build-all.py` after any colour change: the contrast gate
  checks every derived pairing against WCAG AA and aborts when one fails.

## Don't

- **No third-party resources for anything that belongs to the interface** — no
  font imports, no images from foreign CDNs. Not because the app must be offline
  (it works with Git remotes), but because type and imagery should be there on
  the first frame. `tailgrids init` writes a Google Fonts import to the top of
  `tailgrids.css`; it has to be removed again after every run.
- No numbers in Lora without `tnum` enabled — its digits are proportional and
  will wander in columns. Numbers belong in JetBrains Mono.
- Do not set the mark below 20 px, or the lockup with tagline below 200 px.
- Do not change values in this file — `brand.lock.json` is the source.
- No custom border radii outside the scale (no 5 px, 10 px, 15 px).
- No grey text on grey surfaces — 4.5:1 minimum, and the gate checks it.
- No modal stacks deeper than two levels.
- Disable buttons visibly (40 % opacity, `not-allowed`) rather than hiding them.

## Layout

Today the shell is a title bar: the mark, the page's name, its actions on the
right, the theme toggle after them. Content sits as glass cards on the ground,
24–32 px between main sections — tighter than TailGrids' 80–96 px, because
this is a desktop app and not a marketing page.

A sidebar (232 px, 1 px border on the right) is planned for when the analyses
arrive and there is something to navigate between. It was built once and
removed again, because two screens with one way between them do not need a
frame — it comes back as a decision then, not as a placeholder now.

Breakpoints barely matter: the main window starts at 1200 × 800 px with a
900 × 600 minimum, defined in `src-tauri/tauri.conf.json` — that file is the
truth, not this paragraph.
